# 口袋牛牛大冒險

用「口袋」品牌吉祥物紅牛做的橫向捲軸平台遊戲，以 Godot 4.7 開發，可匯出為網頁版。
玩法參考《超級馬利歐》：跑、跳、踩敵人、頂磚塊、吃道具變大，走完一條精心設計的
長關卡。

系列前作：[Game1 口袋大逃亡](../Game1)（閃避求生）、
[Game2 口袋股市守衛](../Game2)（隨機合成塔防）。主角圖與字型沿用前作。

## 玩法

一條約 300 格（十五個畫面寬）的長關卡，走到終點旗竿即通關。四段節奏：

| 段落 | 位置 | 教什麼 |
|---|---|---|
| 教學段 | 0–64 格 | 跑、跳、踩小熊 |
| 道具段 | 65–145 格 | 頂磚塊、變大、丟金幣、閃地刺與刺球 |
| 立體段 | 146–252 格 | 移動平台、水管暗房、跌停箭頭 |
| 關底段 | 253–299 格 | Boss熊 |

操作：

| 按鍵 | 動作 |
|---|---|
| ←→ 或 A D | 移動 |
| 空白鍵 或 W | 跳（按越久跳越高） |
| Shift 或 J | 丟金幣（只有大牛能丟） |
| ↓ 或 S | 站在水管上進入暗房 |

**金幣同時是分數與彈藥。** 每枚 50 分，丟一發消耗一枚。撿到的金幣要留著換分
還是拿去打怪，是個真的取捨。

**吃到漲停牛奶會變大。** 變大之後撞到敵人只會變回小牛並短暫無敵，不會直接死，
而且解鎖丟金幣。一個道具解鎖兩件事，所以不需要第三階道具。

**刺球不能踩。** 小熊和跌停箭頭可以踩，刺球只能繞過或用金幣打掉。如果所有敵人
都能踩，玩家會養成「看到就跳上去」的反射，關卡就沒有辨識的樂趣了。

**Boss 要踩三次或用金幣打六發。** 兩條路都留著：把金幣丟光了還是能靠踩踏過關，
不會卡在關底。Boss 活著的時候旗竿是暗的、碰不到。

## 開發

需要 Godot 4.7.2。開啟專案：

    /Users/hongming/Downloads/Godot.app/Contents/MacOS/Godot --path .

完整驗證（語法檢查 → 單元測試 → 整合測試），改完程式跑這個：

    tools/verify_game.sh

只跑單元測試（**用這個腳本，不要直接呼叫 GUT**，原因見腳本開頭註解）：

    tools/run_tests.sh

不開視窗確認畫面（存成 PNG）。第三個參數是模式（`title` / `game` / `big`），
第四個參數把玩家往右移動指定格數，用來逐段檢查長關卡：

    Godot --path . tools/capture.tscn -- /tmp/shot.png 60 game 168

重新產生美術資產（詳見 [tools/README.md](tools/README.md)）：

    tools/.venv/bin/python tools/prepare_assets.py

重新組裝主關卡：

    python3 tools/build_level1.py

## 匯出網頁版

需要先安裝 Godot 4.7.2 的匯出範本。網頁版必須經由 HTTP 提供，
直接開 `file://` 會因為跨來源限制而失敗：

    mkdir -p build/web
    Godot --headless --path . --export-release "Web" build/web/index.html
    python3 -m http.server 8000 --directory build/web

然後開啟 <http://localhost:8000>。

## 專案結構

| 路徑 | 內容 |
|---|---|
| `scripts/` | 不繼承 `Node` 的純運算類別，單元測試對象 |
| `scenes/` | 遊戲場景與其腳本 |
| `levels/` | 純文字關卡檔 |
| `assets/` | 由 `tools/prepare_assets.py` 產生的圖，以及主角圖與字型 |
| `test/unit/` | GUT 單元測試 |
| `tools/` | 資產處理、關卡組裝、測試把關、擷圖工具 |
| `docs/superpowers/` | 設計規格與實作計畫 |

## 架構重點

**純邏輯與節點分離。** 手感物理、狀態轉移、計分、關卡解析、磚塊規則全在
`scripts/` 下不繼承 `Node` 的類別裡，節點腳本只負責讀輸入、呼叫這些類別、
更新畫面。單元測試因此不需要建立場景樹就能跑。手感的十三個參數集中在
`scripts/player_physics.gd` 頂端，調整改一個數字重跑即可。

**訊號單向往上。** `Player`、`Enemy`、`HUD`、磚塊只發訊號，由 `Main` 接手改狀態。
子節點不知道 `Main` 存在，因此可以獨立運作與測試。

**關卡是純文字，不是 TileMap 場景。** 一個字元一格，`scripts/level_map.gd` 解析成
純資料、`scenes/level_builder.gd` 建構成節點。這樣關卡能 diff、改一個字元就能試
手感、不需要圖形編輯器就能排版。代價是要維護一張字元表，那張表就是
`scripts/tile_glossary.gd`，也是全專案唯一的真相來源。

**關卡內容本身也有測試。** `test/unit/test_level1_content.gd` 驗收主關卡：所有機制
都到齊、教學段不出現進階危險物、Boss 在旗竿之前、至少兩個檢查點，以及沒有任何
坑超過 4 格寬——跳躍高度 236 px、跑速 280 px/s 換算滿跳水平最遠 5.1 格，留一格
安全邊際。排版排壞了會在這裡被抓到，不必等玩到那一段才發現。

**主角沒有逐格動畫。** 待機、跑、跳、落地、受傷全是程式化的擠壓拉伸，只用一張
`red_bull.png`。紅牛是圓球造型，squash-stretch 在它身上特別討喜；日後要換成
`AnimatedSprite2D`，遊戲邏輯一行都不用動。

## 關卡字元表

`scripts/tile_glossary.gd` 是唯一真相，解析器遇到表外字元直接報錯。

| 字元 | 意義 |
|---|---|
| （空白） | 空 |
| `#` | 地面 |
| `=` | 磚台 |
| `?` | 問號磚（頂出金幣） |
| `M` | 牛奶磚（頂出漲停牛奶，外觀與問號磚相同） |
| `x` | 可破磚（大牛才頂得碎） |
| `^` | 地刺 |
| `o` | 金幣 |
| `b` | 小熊（可踩） |
| `s` | 盤面刺球（不可踩） |
| `a` | 跌停箭頭（會俯衝，可踩） |
| `P` / `V` | 水平／垂直移動平台 |
| `1`–`9` | 可進水管，編號對應中繼資料的 `pipeN` |
| `C` | 檢查點 |
| `S` | 玩家起點（全關卡恰好一個） |
| `F` | 終點旗竿 |
| `K` | Boss熊 |

中繼資料寫在 `---` 之前，一行一組 `key: value`：`name`、`time`、`pipeN`，
以及水管暗房用的 `room: true`（跳過起點與終點驗證）。
