# 口袋牛牛大冒險

**線上試玩：<https://panda0909.github.io/pocket-game-test2/>**

用「口袋」品牌吉祥物做的橫向捲軸平台遊戲，以 Godot 4.7 開發，可匯出為網頁版。
玩法參考《超級馬利歐》：跑、跳、踩敵人、頂磚塊、吃道具變大，走完一條精心設計的
長關卡。

系列前作：[Game1 口袋大逃亡](../Game1)（閃避求生）、
[Game2 口袋股市守衛](../Game2)（隨機合成塔防）。主角圖與字型沿用前作。

## 玩法

開始前可以從**三隻主角**裡挑一隻，各有一點手感差異：

| 角色 | 差異 |
|---|---|
| 紅牛 | 開局多兩枚金幣，一開始就有彈藥 |
| 綠恐龍 | 衝刺速度 +8% |
| 橘壁虎 | 土狼時間多 0.06 秒，踏出平台邊緣後更晚仍能起跳 |

碰撞箱、跳躍高度與走路速度三隻完全相同，差異只往「一樣或更寬鬆」的方向走。
這是硬性約束，不是巧合：關卡的幾何驗收（跳躍距離、磚台高度、大牛淨空）是照
一組數值算出來的，某隻角色只要跳得低或跑得慢，同一張關卡對牠就可能有過不去
的地方，而測試只驗了基準那一組。`test/unit/test_roster.gd` 有一條測試釘著它，
把任何一隻調得比基準難就會失敗。

一條約 300 格（十五個畫面寬）的長關卡，走到終點旗竿即通關。四段節奏：

| 段落 | 位置 | 教什麼 |
|---|---|---|
| 教學段 | 0–64 格 | 跑、跳、踩小熊 |
| 道具段 | 65–145 格 | 頂磚塊、變大、丟金幣、閃地刺與刺球 |
| 立體段 | 146–252 格 | 移動平台、水管暗房、跌停箭頭 |
| 關底段 | 253–299 格 | Boss熊 |

操作：

| 按鍵 | 手把 | 動作 |
|---|---|---|
| ←→ 或 A D | 十字鍵／左搖桿 | 移動（選角畫面用來換角色） |
| 空白鍵、W 或 ↑ | A | 跳（按越久跳越高） |
| Shift | RB | 衝刺（1.5 倍速，小牛也能衝） |
| Z | X | 丟金幣（只有大牛能丟） |
| ↓ 或 S | 十字鍵下 | 站在水管上進入暗房（選角畫面用來回到標題） |
| ESC 或 P | Start | 暫停（含音效與音樂音量） |

行動裝置有虛擬按鍵，只在偵測到觸控螢幕時出現。

**衝刺與丟金幣是兩個鍵。** 早期版本仿《超級馬利歐》的 B 鍵一鍵兩用（按住衝刺、
按下丟金幣），但代價比預期大：金幣是有限彈藥、Boss 需要六發，習慣按住 Shift 跑
的玩家會在抵達關底前把彈藥灑光，而且完全不知道是自己造成的。

**金幣同時是分數與彈藥。** 撿到記 50 分，丟出去退還那 50 分並消耗一枚。
撿到的金幣要留著換分還是拿去打怪，是個真的取捨。

**有音效與背景音樂。** 18 個 8-bit 方波音效加一段循環 BGM，全部由
`tools/prepare_audio.py` 用純標準函式庫合成——和美術走同一套「素材可重現、
來源留在版本庫裡」的做法，不必去記是從哪個網站下載的。音量在暫停選單裡調，
設定存在 `user://settings.cfg`。

**成績會存檔。** 最高分、最多金幣、是否通關與最佳剩餘秒數存在 `user://save.cfg`，
標題畫面顯示。刷分要有對照組才有意義。

**吃到漲停牛奶會變大。** 變大之後撞到敵人只會變回小牛並短暫無敵，不會直接死，
而且解鎖丟金幣。一個道具解鎖兩件事，所以不需要第三階道具。

**刺球不能踩。** 小熊和跌停箭頭可以踩，刺球只能繞過或用金幣打掉。如果所有敵人
都能踩，玩家會養成「看到就跳上去」的反射，關卡就沒有辨識的樂趣了。

**Boss 要踩三次或用金幣打六發。** 兩條路都留著：把金幣丟光了還是能靠踩踏過關，
不會卡在關底。Boss 活著的時候旗竿是暗的、碰不到。

## 分享成績

通關或遊戲結束後，選單有四個動作：**分享到 Facebook｜分享到 Threads｜複製成績文字｜再玩一次**
（←→ 選、空白鍵確定，滑鼠也能點）。游標預設停在「再玩一次」，所以連按兩下空白鍵重來的
習慣仍然有效。

三個平台的能力差很多，實作上不假裝它們一樣：

| 平台 | 做法 | 限制 |
|---|---|---|
| Threads | `threads.net/intent/post?text=` 官方 web intent | 文字會完整預填 |
| Facebook | `sharer.php?u=` 分享視窗 | **不吃我們給的文字**，只讀網址的 OG 標籤 |
| Instagram | 複製成績文字到剪貼簿，玩家自己貼 | **Instagram 沒有任何網頁分享網址可以預填貼文** |

所以 Facebook 的分享長相完全取決於 OG 標籤：`export_presets.cfg` 的 `html/head_include`
會在每次匯出時把 `og:title` / `og:description` / `og:image` 注入 `<head>`，預覽圖是
`tools/prepare_assets.py` 產生的 `assets/share_cover.png`（1200×630，OG 標準比例），
由 `tools/publish_pages.sh` 複製到網站根目錄。

**彈出視窗被擋時會直接導覽當前分頁。** Godot 把瀏覽器輸入排進自己的幀迴圈才處理，
`window.open` 的呼叫已經離開使用者手勢，瀏覽器有理由擋它。被擋是偵測得到的
（`window.open` 回 `null`），所以只在真的被擋時才離開遊戲——分數已經定案，按上一頁就回來了。

## 開發

需要 Godot 4.7.2。腳本會自動尋找 Godot（PATH、`/Applications`、`~/Downloads`），
找不到的話用環境變數指定：

    GODOT=/path/to/Godot tools/verify_game.sh

開啟專案：

    godot --path .

Python 工具的相依套件：

    python3 -m venv tools/.venv
    tools/.venv/bin/pip install -r tools/requirements.txt

完整驗證（語法檢查 → 單元測試 → 整合測試），改完程式跑這個：

    tools/verify_game.sh

只跑單元測試（**用這個腳本，不要直接呼叫 GUT**，原因見腳本開頭註解）：

    tools/run_tests.sh

不開視窗確認畫面（存成 PNG）。第三個參數是模式（`title` / `game` / `big`），
第四個參數把玩家往右移動指定格數，用來逐段檢查長關卡：

    Godot --path . tools/capture.tscn -- /tmp/shot.png 60 game 168

重新產生美術資產（詳見 [tools/README.md](tools/README.md)）：

    tools/.venv/bin/python tools/prepare_assets.py

重新組裝主關卡：

    python3 tools/build_level1.py

重新產生音效與背景音樂：

    python3 tools/prepare_audio.py

重新產生字型子集（改了介面文字之後）：

    tools/.venv/bin/python tools/prepare_font.py

每次 push 都會在 GitHub Actions 上跑一次 `tools/verify_game.sh`
（見 `.github/workflows/verify.yml`）。

## 匯出網頁版

需要先安裝 Godot 4.7.2 的匯出範本。網頁版必須經由 HTTP 提供，
直接開 `file://` 會因為跨來源限制而失敗：

    mkdir -p build/web
    Godot --headless --path . --export-release "Web" build/web/index.html
    python3 -m http.server 8000 --directory build/web

然後開啟 <http://localhost:8000>。

## 發佈到 GitHub Pages

    tools/publish_pages.sh

這支腳本會重新匯出，然後把產物推到 `gh-pages` 分支（每次重建成單一 commit，
避免每發佈一次就在歷史裡多存一份將近 40 MB 的 wasm）。`main` 只放原始碼。

**匯出設定的 `variant/thread_support` 必須維持 `false`。** GitHub Pages 沒辦法
設定 COOP／COEP 標頭，開了執行緒支援的版本在上面會載不起來。

## 專案結構

| 路徑 | 內容 |
|---|---|
| `scripts/` | 不繼承 `Node` 的純運算類別，單元測試對象 |
| `scenes/` | 遊戲場景與其腳本 |
| `levels/` | 純文字關卡檔 |
| `assets/` | 由 `tools/prepare_assets.py` 產生的圖，以及主角圖與字型 |
| `test/unit/` | GUT 單元測試 |
| `tools/` | 資產處理、關卡組裝、測試把關、擷圖工具 |
| `docs/superpowers/` | 設計規格與實作計畫 |

## 架構重點

**純邏輯與節點分離。** 手感物理、狀態轉移、計分、關卡解析、磚塊規則全在
`scripts/` 下不繼承 `Node` 的類別裡，節點腳本只負責讀輸入、呼叫這些類別、
更新畫面。單元測試因此不需要建立場景樹就能跑。手感的十三個參數集中在
`scripts/player_physics.gd` 頂端，調整改一個數字重跑即可。

**訊號單向往上。** `Player`、`Enemy`、`HUD`、磚塊只發訊號，由 `Main` 接手改狀態。
子節點不知道 `Main` 存在，因此可以獨立運作與測試。

**關卡是純文字，不是 TileMap 場景。** 一個字元一格，`scripts/level_map.gd` 解析成
純資料、`scenes/level_builder.gd` 建構成節點。這樣關卡能 diff、改一個字元就能試
手感、不需要圖形編輯器就能排版。代價是要維護一張字元表，那張表就是
`scripts/tile_glossary.gd`，也是全專案唯一的真相來源。

**幾何約束寫成測試。** 大牛碰撞箱高 168 px，所以可頂的磚塊底下必須留 3 格淨空，
否則小牛鑽得過去、變大後卻會嵌在磚裡。站得上去的磚台不能高過 236 px 的跳躍上限，
超過的就得有移動平台當中繼。這兩條都由 `test/unit/test_level_geometry.gd` 守著，而且對 `levels/` 底下每個
關卡檔都跑一遍——它們是推算碰撞箱與跳躍高度才發現的，不是玩出來的。
同一支測試還守著「磚台邊緣不得懸在坑上方」：玩家站在高處時相機被夾住、關卡
底部完全在畫面外，看不到下面是什麼就踩空了。

**關卡內容本身也有測試。** `test/unit/test_level1_content.gd` 驗收主關卡：所有機制
都到齊、教學段不出現進階危險物、Boss 在旗竿之前、至少兩個檢查點，以及沒有任何
坑超過 4 格寬——跳躍高度 236 px、跑速 280 px/s 換算滿跳水平最遠 5.1 格，留一格
安全邊際。排版排壞了會在這裡被抓到，不必等玩到那一段才發現。

**三隻主角共用碰撞箱與幾何。** `scripts/roster.gd` 是角色清單與手感差異的唯一
真相。差異只有衝刺速度、土狼時間與初始金幣三項，而且只往寬鬆的方向走；跳躍高度
與走路速度不動，關卡的幾何驗收因此仍然只要跑一組數值。每隻角色都有裝備待機、
走路與變身三組 sprite，全部整理成 180 px 高，所以 `BASE_SPRITE_SCALE` 直接適用。

**主角有狀態圖片切換。** 在地面移動時，待機圖與走路圖交替切換；吃到牛奶時切到
獨立的變身圖，受傷縮回小牛時切回裝備待機圖。圖像本身包含帽子、工作服、手套、
腰帶與靴子，避免用幾何圖形硬疊在角色上。

## 關卡字元表

`scripts/tile_glossary.gd` 是唯一真相，解析器遇到表外字元直接報錯。

| 字元 | 意義 |
|---|---|
| （空白） | 空 |
| `#` | 地面 |
| `=` | 磚台 |
| `?` | 問號磚（頂出金幣） |
| `M` | 牛奶磚（頂出漲停牛奶，外觀與問號磚相同） |
| `x` | 可破磚（大牛才頂得碎） |
| `^` | 地刺 |
| `o` | 金幣 |
| `b` | 小熊（可踩） |
| `s` | 盤面刺球（不可踩） |
| `a` | 跌停箭頭（會俯衝，可踩） |
| `P` / `V` | 水平／垂直移動平台 |
| `1`–`9` | 可進水管，編號對應中繼資料的 `pipeN` |
| `C` | 檢查點 |
| `S` | 玩家起點（全關卡恰好一個） |
| `F` | 終點旗竿 |
| `K` | Boss熊 |

中繼資料寫在 `---` 之前，一行一組 `key: value`：`name`、`time`、`pipeN`、
水管暗房用的 `room: true`（跳過起點與終點驗證），以及暗房的 `entry: x,y`（玩家
從水管進來時站的格子）。

**`---` 分界線是必要的。** `#` 在中繼資料區是註解、在地圖區是地面磚，沒有分界線
就無從分辨——以前找不到分界線時會把全部當地圖，結果是有人寫了一行註解卻得到
一整排地面加上一串「未知字元」錯誤。
