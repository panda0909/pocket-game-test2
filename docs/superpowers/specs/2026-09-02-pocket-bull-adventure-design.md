# 口袋牛牛大冒險 — 設計規格

2026-09-02

以「口袋」品牌吉祥物紅牛為主角的橫向捲軸平台遊戲，Godot 4.7 開發，匯出網頁版。
延續 Game1（口袋大逃亡）與 Game2（口袋股市守衛）的素材與架構慣例。

## 目標與範圍

一條精心設計的長關卡，走完即通關。核心價值在跑跳踩踏的手感，不在關卡數量。
機制取「全餐」：核心跑跳踩踏、變身道具、問號磚、投射物、移動平台、水管隱藏房、
關卡計時、關底 Boss。

**不做**：多關卡選單、關卡進度存檔、程序化關卡生成、逐格繪製的角色圖集、
觸控操作、網路連線。

## 技術決策

| 項目 | 決定 | 理由 |
|---|---|---|
| 引擎 | Godot 4.7.2，`gl_compatibility` | 與前兩案一致，網頁匯出穩定 |
| 視窗 | 1280×720 橫向 | 平台遊戲需要水平視野；直式看不到前方地形等於盲跳 |
| 拉伸 | `canvas_items` ＋ `aspect = keep` | **與 Game2 的 `expand` 不同**：視野寬度必須固定，否則關卡難度隨視窗大小改變 |
| 操作 | 純鍵盤 | 方向鍵／WASD 移動、空白鍵跳、Shift 丟金幣 |
| 格子 | 64 px | 視野 20×11.25 格，牛的造型在此尺寸辨識度足夠 |
| 主角動畫 | 單張圖 ＋ 程式化擠壓拉伸 | 零新素材；圓球造型特別適合 squash-stretch。日後換 `AnimatedSprite2D` 不動遊戲邏輯 |
| 敵人與背景 | Pillow 程式化 Q 版 | 統一在牛的卡通調性；Game2 的熊是寫實暗黑風，平台遊戲貼近觀看會風格衝突 |
| 關卡資料 | 純文字字元地圖 | 可版控、可 diff、解析器可單元測試；不需要圖形編輯器 |

## 架構

兩條規則沿用前兩案，實作時不破例：

1. **純邏輯與節點分離**。所有數學（物理積分、狀態轉移、計分、關卡解析）放在
   `scripts/` 下不繼承 `Node` 的類別，節點腳本只讀輸入、呼叫這些類別、更新畫面。
   單元測試因此不必建立場景樹。
2. **訊號單向往上**。`Player`、`Enemy`、`HUD` 只發訊號，由 `Main` 接手改狀態。
   子節點不知道 `Main` 存在，可獨立運作與測試。

### 資料流

`levels/level1.txt` →（`LevelMap.parse`）→ 純資料 →（`LevelBuilder`）→
`TileMapLayer` ＋ 實體節點。

遊玩中 `Player` 每幀把輸入狀態交給 `PlayerPhysics.step()` 算出新速度，回寫
`velocity` 後呼叫 `move_and_slide()`。碰撞事件由節點發訊號給 `Main`，`Main`
更新 `RunStats` 並通知 `HUD`。

## 玩家物理

小牛高 2 格（碰撞箱 56×120），大牛 ×1.4（碰撞箱 56×170）。
常數集中在 `PlayerPhysics` 頂端，調手感改一個數字重跑即可。

| 參數 | 值 | 作用 |
|---|---|---|
| 最高跑速 | 280 px/s | ≈4.4 格/秒 |
| 地面加速／煞停 | 1600／2000 px/s² | 有慣性但不打滑 |
| 空中加速 | 1100 px/s² | 空中操控刻意弱於地面 |
| 跳躍初速 | −720 px/s | 按滿約 3.7 格高 |
| 上升／下降重力 | 1100／1800 px/s² | 下降比上升重，弧線俐落 |
| 放開跳鍵 | 上升速度夾到 −420 | 輕點約 1.3 格，形成可變跳躍高度 |
| 終端下墜 | 900 px/s | 長墜落仍看得清落點 |
| 土狼時間 | 0.10 s | 踏出邊緣後仍可跳 |
| 跳躍緩衝 | 0.12 s | 落地前按跳，落地即彈 |
| 踩敵回彈 | −480（按住跳 −640） | 按住能連踩爬高 |

`PlayerPhysics.step()` 是純函式：吃 `(速度, 輸入, 是否在地面, delta, 計時器狀態)`，
回傳新速度與新計時器狀態。土狼時間與跳躍緩衝的計時器也在裡面推進，不放節點。

## 玩家狀態機

狀態 `SMALL` / `BIG`，外加 1.2 秒無敵旗標（期間 alpha 閃爍）。

| 事件 | SMALL | BIG |
|---|---|---|
| 撞到敵人 | 死亡 | 變 SMALL ＋ 1.2 s 無敵 |
| 無敵中撞到敵人 | 無事 | 無事 |
| 吃漲停牛奶 | 變 BIG | ＋1000 分 |
| 踩到敵人 | 敵人死，回彈 | 敵人死，回彈 |
| 掉出畫面下緣 | 死亡 | 死亡 |

**丟金幣是 BIG 專屬能力，消耗撿到的金幣當彈藥**（每發 1 枚，0 枚時按了沒反應）。
金幣同時是分數與彈藥，玩家得取捨；道具因此有兩層價值（變耐打＋解鎖攻擊），
不必再做第三階道具。

死亡扣一命，退回關卡起點或最後通過的檢查點。生命歸零回到開始畫面。

## 擠壓拉伸動畫

全部在 `player.gd` 用 Tween 與 `scale` 做，不需新素材：

| 情境 | 表現 |
|---|---|
| 待機 | scale 1.0 ↔ 1.03 呼吸，週期 1.6 s |
| 跑步 | 垂直彈跳位移，同時橫向 1.06／縱向 0.94 交替，頻率隨速度 |
| 起跳瞬間 | 壓成 (0.82, 1.22)，0.15 s 彈回 |
| 落地瞬間 | 壓成 (1.25, 0.78)，0.18 s 彈回 |
| 下墜 | 微拉長 (0.94, 1.06) |
| 轉向 | 翻 `scale.x` 正負 |
| BIG | 整體 ×1.4 |
| 無敵 | alpha 在 0.35 ↔ 1.0 間閃爍 |

## 關卡格式

中繼資料在前，`---` 之後是地圖，一字元一格。地圖左下角對齊關卡底部。

```
name: 盤面大道
time: 300
pipe1: level1_pipe_a
---
                    ?x?
        o o o              b        F
     P>            ====          ====
##########  ^^  ###########   1  #####
```

`tile_glossary.gd` 是字元語意的唯一真相，解析器遇到表外字元直接報錯。

| 字元 | 意義 | 行為 |
|---|---|---|
| （空白） | 空 | 無碰撞 |
| `#` | 地面 | 實心 |
| `=` | 磚台 | 實心 |
| `?` | 問號磚 | 頂一次彈出金幣，之後變實心用過磚 |
| `M` | 牛奶磚 | 頂一次彈出漲停牛奶 |
| `x` | 可破磚 | SMALL 頂會反彈，BIG 頂碎 |
| `^` | 尖刺 | 觸即受傷（等同撞敵人） |
| `o` | 金幣 | ＋1 枚、＋50 分 |
| `b` | 小熊 | 水平巡邏 60 px/s，探到平台邊緣轉向；可踩死，＋100 分 |
| `s` | 盤面刺球 | **不可踩**（踩到受傷），金幣可打掉 |
| `a` | 跌停箭頭 | 懸空，玩家進入水平範圍即俯衝；可踩死 |
| `P` | 水平移動平台 | 來回 4 格 |
| `V` | 垂直移動平台 | 來回 3 格 |
| `1`–`9` | 可進水管 | 站上按 ↓ 進入，編號對應中繼資料 `pipeN` |
| `C` | 檢查點 | 通過後死亡從此重生 |
| `S` | 玩家起點 | 全關卡恰好一個 |
| `F` | 終點旗竿 | 接觸通關，剩餘時間 ×10 換分 |
| `K` | Boss熊 | 關底，踩 3 次或金幣打 6 發 |

### 解析輸出與驗證

`LevelMap.parse(text)` 回傳純資料：地形二維陣列、實體清單 `{type, cell, params}`、
中繼資料字典、起點座標；解析失敗回傳錯誤訊息陣列而不丟例外。

驗證規則（皆有單元測試）：

- 恰好一個 `S`，否則錯誤
- 至少一個 `F` 或一個 `K`，否則錯誤
- 表外字元 → 錯誤，訊息含行列座標
- `1`–`9` 必須有對應的 `pipeN` 中繼資料，否則錯誤
- `time` 必須是正整數，缺少時預設 300

## 關卡設計

主關卡約 300 格寬 × 14 格高（約 15 個畫面寬），分四段節奏：

1. **教學段**（0–60 格）：只有平地、單格落差、兩隻小熊。學會跑、跳、踩。
2. **道具段**（60–140 格）：問號磚與可破磚、第一個牛奶磚、尖刺、刺球。學會頂磚、變大、丟金幣。
3. **立體段**（140–250 格）：移動平台、深坑、水管隱藏房、跌停箭頭。垂直操作與冒險取捨。
4. **關底段**（250–300 格）：Boss熊與旗竿。

隱藏房 `level1_pipe_a.txt` 是約 20×8 格的小房間，內有一排金幣與一個牛奶磚，
房內出口水管送回主關卡水管的右側地面。

## 相機

`Camera2D` 水平跟隨，帶前視偏移（依移動方向偏 120 px）；垂直只在玩家離開畫面
中央帶（上下各 80 px）時才跟隨。用 `limit_left/right/top/bottom` 夾在關卡邊界內，
避免看到關卡外的空白。

## HUD 與流程

HUD 顯示分數、金幣數、生命數、剩餘時間。計時每秒減 1，歸零即死亡。

`Main` 的流程狀態：`TITLE` → `PLAYING` → （`DEAD` → `PLAYING` 或 `GAME_OVER`）
→ `CLEARED`。標題與結束畫面用同一個 `CanvasLayer` 切換文字，不另建場景。

## 測試策略

沿用兩案的三層驗證，`tools/verify_game.sh` 一次跑完：語法檢查 → 單元測試 → 整合測試。

**單元測試**（GUT，`test/unit/`，對象全是 `scripts/` 的純邏輯）：

- `test_tile_glossary.gd`：字元查表、未知字元、實心判定
- `test_level_map.gd`：解析正確性、四條驗證規則、中繼資料預設值、左下角對齊
- `test_player_physics.gd`：加速到上限、煞停、跳躍高度符合設計值、放開跳鍵的速度夾制、
  上升與下降重力不同、土狼時間窗、跳躍緩衝窗、終端下墜夾制
- `test_player_state.gd`：狀態轉移表每一格、無敵期間免傷、無敵倒數
- `test_run_stats.gd`：計分、金幣增減、彈藥不足、生命扣減、計時歸零

**整合測試**（`tools/integration_check.gd`，headless）：主場景能載入、主關卡能解析並
建構出預期數量的實體、玩家能落地、踩敵人會回彈、撿金幣會加分、走到旗竿會通關。

**擷圖確認**（`tools/capture.tscn`）：不開視窗存成 PNG，確認畫面與素材對得上。
